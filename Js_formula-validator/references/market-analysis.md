# 公式验证工具市场分析

调研时间：2026-10。调研对象为指令中指定的 `SymKit`、`AXIOM neuro-symbolic`、
`math-physics-complete`，以及检索中浮现的两个相邻方案。结论基于对各项目公开
仓库、README、推荐 system prompt 与论文摘要的直接阅读，而非二手评测。

---

## 1. 调研对象与事实摘要

### SymKit（`LBurny/symkit-mcp`）

定位最接近的竞品，SymPy 之上的 MCP 推导引擎。

- 47 个 MCP 工具，分 10 类；1656 项测试。
- 量纲检查通过 `math(operation="dimension", expression=..., units={...})` 调用。
- **单位从不推断**：必须用 `register_symbol` 或每次调用时传 `units={...}` 显式声明。
  其推荐 system prompt 原文："Units are never inferred — declare them with
  `register_symbol(...)` or per-call `units={...}`"。
- `consistent` 是三态：`false` 判失败，`null` 为 inconclusive（未声明单位即落入此态）。
- 多步推导用 session 链：`session_start` → 逐步记录 → `session_verify_step` →
  `session_complete`；出错时 `session_rollback` 回到上一个好状态。
- 可选 Lean 4 + Mathlib 内核认证，覆盖有理片段的 `simplify / expand / factor /
  combine`，需下载 1–2 GB 工具链。
- 衍生自 `nsforge-mcp`，可与 `sympy-mcp` 并用。

### AXIOM（arXiv:2606.00671，Alessio Bruno）

信任优先的神经符号执行架构，工程纪律最值得借鉴。

- 冻结 Qwen 7B 仅作 **canonicalizer**，把自然语言题面重写成窄 schema；
  确定性 SymPy CAS 管线负责推导与验证。**LLM 从不做决定，只做翻译。**
- 路由采用严格 **1:1:1 对齐**：题目形状正则 ↔ schema 专属 prompt ↔ 闭式 CAS handler，
  已发布 3100+ 组三元组。
- **abstain 是一等输出**：解析不了就返回 `UNKNOWN`，不存在第三种状态。
- `LOST_CORRECT` 扫描作为回归预言机，250+ 次连续提交零回归。
- MATH 基准（4 类 2747 题）：正确率 94.36%，可解析题 100% 可信，
  **零 confident-wrong**；规则型 handler 中位延迟 1 ms。
- 面向竞赛数学（代数、数论、计数概率、预科），**不含物理量纲与极限分析**。

### math-physics-complete / `solve-physics-problem`（`zzr2718281828/claude-physics`）

这是本次调研中最关键的发现，也是最容易被误认为「已有方案」的一个。

- 其 `核心原则` 第 5 条与 `结果讨论` 章节明确要求「**必做量纲检查与极限检验**」。
- 但通读 SKILL.md 全文，**没有任何脚本、任何可执行校验**。所谓检查是写给
  大模型的提示词要求，由大模型自己执行。
- 附加资源为 `checklist.md` 与 `solution-template.md`，同样是文档而非代码。

也就是说，它把「量纲检查」交给了会犯量纲错误的那个系统本身。这恰恰是用户抱怨
的幻觉循环：让 AI 检查 AI 的推导，等于用同样的认知路径再走一遍，错误大概率复现。
**它不是「已有方案」，它是问题本身的一个实例。**

### 相邻方案

- `chuk-mcp-physics`：55 个工具，覆盖经典力学、流体、刚体仿真与 62 类单位换算。
  面向**数值仿真**，不做符号验证。
- AxQM（Axiomatic AI）：Nielsen & Chuang 教材规模 Lean 形式化，1019 个机器可检
  证明任务。形式化是最强保证，但门槛是整本教材的手工/自动形式化，且覆盖有限维
  量子力学，无法用于日常随手推导。
- `sympy-mcp`：通用 SymPy MCP 服务，提供符号能力，无验证策略。

| 量纲分析 | 有，单位须手工声明 | 无 | 提示词要求 LLM 自检 | 单位换算，非量纲分析 | 有，单位可推断并逐条回显 |

## 3. 两个核心缺口

### 缺口一：极限情况自动枚举

现状是**要么没有，要么交给 LLM 自己想**。

- SymKit 的推荐 system prompt 通篇未出现 limit / limiting case 的自动枚举。
- AXIOM 的 1:1:1 路由是**闭式模板匹配**：题目形状正则匹配到既有 handler 才有解，
  否则 abstain。它无法对一条从未见过的物理公式做「令 x→0 看看」这类开放动作。
- claude-physics 要求 LLM 自己做极限检验——而「漏掉一个极限情形」正是 LLM 的
  典型失效模式。

**为什么这个缺口致命。** 极限检验的价值在于它能抓到数值对照抓不到的错误：一组
随机点几乎不可能恰好采样到 `x = 1` 这个极点，但错误往往就藏在那里。本技能的做法
是在枚举 0 与 ±∞ 之外，先用 `solve(denominator, x)` 自动求出分母零点并逐点比对
两侧行为——**不需要用户指定可疑点**。

实测：`1/(1-x**2) = 1/(1-x)`（错误的部分分式分解）。工具自动发现 `x = -1` 与
`x = 1`，报出「as x -> -1, the lhs diverges while the rhs stays finite」，以及
两侧同时发散但比值趋于 2 而非 1。

### 缺口二：多步推导断点定位

现状是**能记录，不能定位**。

- SymKit 的 session 链记录了每一步的输入输出，出错时提供 `session_rollback`
  回到上一个好状态。但「回到上一个好状态」需要**使用者自己知道哪一步坏了**——
  它提供的是回滚能力，不是定位能力。
- 其余方案完全没有这个概念。

**为什么这个缺口致命。** 一条 12 步的推导错了，真正昂贵的不是「知道它错了」，
而是「知道第 7 步错了」。回滚到第 6 步再重推，前提是你已经找到了第 7 步。

本技能的做法是**逐对比较**：对链上每一对相邻步骤做数值对照，第一个不符的位置
即断点，并进一步给出成因分类——

| 诊断 | 判据 | 该去查什么 |
|---|---|---|
| `dimension_break` | 该步两侧量纲发生变化 | 漏了带量纲的因子（c、ħ、某个 1/2） |
| `constant_factor` | 量纲未变，但两侧之比在全部样本上近似恒定 | 系数错了 |
| `structural` | 量纲未变，且比值随参数变化 | 函数形式错了，重查代数 |

这个分类把「我知道错了」推进到「我知道该去查哪一类东西」，是本技能最接近
「自动 Debug」的部分。

## 4. 差异化定位

不重复造轮子，只补三个轮子之间的空隙：

1. **把量纲/极限检查从提示词层下沉到执行层。**
   claude-physics 证明了社区已经识别出「该做量纲与极限检查」，但它只做到了提示词。
   本技能把它做成不可绕过的确定性执行，并吸收 AXIOM 的纪律：**做不了就 abstain，
   不许猜**。

2. **把「记录推导」升级为「定位断点」。**
   SymKit 的 session 链提供了完整的可审计数据，本技能补上缺失的那一环：自动
   逐对比较与成因分类。二者是互补的，不是替代的。

3. **把工具面收窄到 4 个。**
   这是 Token 经济学，见下节。

明确**不做**的事：

- 不做形式化认证。Lean + Mathlib 需要 1–2 GB 工具链，且覆盖有理片段；对「随手
  验一条公式」而言代价与收益不成比例。AxQM 的路线值得尊敬，但它是另一类产品。
- 不做数值仿真。那是 `chuk-mcp-physics` 与 SciPy 的领域。
- 不做公式库检索。SymKit 的 SQLite FTS5 公式库已经做得很好，不重复。

## 5. Token 经济学：为什么工具数量本身就是成本

MCP 的工具 schema 会随每次 `tools/list` 注入上下文，并在挂载该服务器的**每一轮
对话**中持续占用。经验量级：单个工具 schema 约 150–400 token。

| 方案 | 工具数 | schema 常驻开销（估算） |
|---|---|---|
| SymKit | 47 | 约 7k–19k token |
| chuk-mcp-physics | 55 | 约 8k–22k token |
| **本技能** | **4** | **约 1–2k token** |

这不是一次性开销，而是**每轮对话都要付的租金**。一条公式的验证摘要只有几百
token，若工具 schema 本身就要上万 token，那么「用工具省下的推理成本」会被
「工具常驻成本」吃掉——尤其在日常随手验证这种高频、短交互的场景。

因此本技能的第二个设计约束是**输出也要省**：命令行只打印一行紧凑 JSON 摘要
（实测 < 900 字符），完整的高亮报告落盘。摘要用于判断是否通过，报告只在需要
细节时才打开。这两件事合起来，才让「每推一条公式就验一次」在经济上成立。
